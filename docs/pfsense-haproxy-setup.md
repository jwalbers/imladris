# pfSense HAProxy Setup — Imladris Lab

HAProxy configuration for routing `imladrislab.org` and subdomains through the
Oregon pfSense firewall alongside the existing `ha.bipeds.org` (Home Assistant).

Reference files in this directory:
- `haproxy/haproxy-imladris.cfg` — annotated reference/template config
- `haproxy/haproxy-generated.cfg` — latest validated pfSense-generated config

## pfSense HAProxy GUI Setup

### Prerequisites

1. Install the **ACME** package and obtain a wildcard cert:
   - Domain: `imladrislab.org`
   - SAN: `*.imladrislab.org`
   - Method: DNS-01 via name.com API
   - Add cert to `HA_Frontend.crt_list` via HAProxy → Frontend → SSL Offloading

2. Add DNS A records at name.com:
   - `@` → `68.116.51.146` (root domain)
   - `*` → `68.116.51.146` (all subdomains)

### Backends (Services → HAProxy → Backend)

Create one backend per service. Clone the first and update Name / server name / Port.

| Backend name | Server name | Address | Port | Server timeout |
|---|---|---|---|---|
| `Imladris_Landing` | `landing` | `192.168.1.11` | `8090` | `30s` |
| `Imladris_OpenMRS` | `openmrs` | `192.168.1.11` | `8080` | `120s` |
| `Imladris_OrtMod` | `ortmod` | `192.168.1.11` | `8042` | `60s` |
| `Imladris_OrtPACS` | `ortpacs` | `192.168.1.11` | `8043` | `300s` |
| `Imladris_OHIF` | `ohif` | `192.168.1.11` | `3000` | `60s` |
| `Imladris_Console` | `console` | `192.168.1.11` | `5001` | `60s` |

Leave all other fields at defaults. Health check type: HTTP (default) is fine.

### Frontend ACLs (Services → HAProxy → Frontend → Edit `HA_Frontend`)

Add these ACLs in the ACL table. All use **Host str** (exact match) except where noted.

| ACL name | Type | Value |
|---|---|---|
| `aclcrt_HA_Frontend` | Host regex | `^(imladrislab\.org\|.*\.imladrislab\.org)(:([0-9]){1,5})?$` |
| `is_imladris_landing` | Host str | `imladrislab.org` |
| `is_imladris_openmrs` | Host str | `openmrs.imladrislab.org` |
| `is_imladris_orthanc_m` | Host str | `orthanc-m.imladrislab.org` |
| `is_imladris_orthanc_p` | Host str | `orthanc-p.imladrislab.org` |
| `is_imladris_ohif` | Host str | `ohif.imladrislab.org` |
| `is_imladris_console` | Host str | `console.imladrislab.org` |

> **The `aclcrt_HA_Frontend` duplicate is intentional** — see quirks section below.

### Frontend use_backend Actions

Add one action per service. Condition = host ACL only (no cert ACL — pfSense adds it automatically):

| Action | Backend | Condition |
|---|---|---|
| use_backend | `Imladris_Landing` | `is_imladris_landing` |
| use_backend | `Imladris_OpenMRS` | `is_imladris_openmrs` |
| use_backend | `Imladris_OrtMod` | `is_imladris_orthanc_m` |
| use_backend | `Imladris_OrtPACS` | `is_imladris_orthanc_p` |
| use_backend | `Imladris_OHIF` | `is_imladris_ohif` |
| use_backend | `Imladris_Console` | `is_imladris_console` |

### Frontend Advanced Pass Thru

```
acl is_imladris_openmrs_auth hdr(host) -m str -i openmrs.imladrislab.org
acl is_imladris_domain hdr(host) -m reg -i ^(imladrislab\.org|.*\.imladrislab\.org)$
http-request auth realm ImladrisLab if is_imladris_domain !{ http_auth(imladris_users) } !is_imladris_openmrs_auth
```

> **Important:** `is_imladris_domain` scopes the auth to imladrislab.org requests only.
> Without it, ALL traffic through the frontend (including ha.bipeds.org) gets challenged,
> which silently breaks the Home Assistant Companion App.

### Global Advanced Pass Thru (Settings page)

```
userlist imladris_users
    user imladris password $apr1$REPLACE_WITH_HASH
```

Generate a password hash: `openssl passwd -apr1 'yourpassword'`

When PIH Entra credentials are available, remove this block and the
`http-request auth` line from the Frontend pass thru. See `docs/entra-auth.md`.

## pfSense HAProxy Quirks Discovered

Hard-won knowledge — document this so nobody has to rediscover it.

### 1. pfSense auto-appends `aclcrt_HA_Frontend` to all `use_backend` conditions

Every `use_backend` rule generated by pfSense gets `aclcrt_HA_Frontend` appended
automatically. Since there is only one frontend, pfSense's auto-generated
`aclcrt_HA_Frontend` only matches `ha.bipeds.org` — so all imladris
`use_backend` rules would silently fail.

**Fix:** Add a second ACL named `aclcrt_HA_Frontend` in the GUI with the
imladrislab.org regex. HAProxy ORs duplicate ACL names, so `aclcrt_HA_Frontend`
becomes a combined match for both `ha.bipeds.org` AND `imladrislab.org`.

### 2. pfSense strips `use_backend` directives from Frontend Advanced Pass Thru

pfSense "owns" use_backend configuration and silently removes any `use_backend`
lines from the Advanced Pass Thru field. Only `acl` and `http-request` directives
survive in the pass thru.

**Fix:** All `use_backend` rules must go through the GUI actions table (where pfSense
will auto-append `aclcrt_HA_Frontend` — see quirk #1 for how that's handled).

### 3. Frontend Advanced Pass Thru is inserted BEFORE GUI-defined ACLs

Content in the Frontend Advanced Pass Thru appears in the generated config before
the ACLs defined in the GUI ACL table. Any ACL referenced in the pass thru that is
only defined in the GUI will fail with "no such ACL".

**Fix:** Any ACL needed by pass thru directives must also be defined in the pass thru,
using `hdr(host)` rather than `var(txn.txnhost)` to avoid the set-var ordering
dependency (see quirk #4).

### 4. `http-request set-var(txn.txnhost)` runs after the Advanced Pass Thru

pfSense generates `http-request set-var(txn.txnhost) hdr(host)` from the GUI, but
this line appears after the Advanced Pass Thru content. Any ACL using
`var(txn.txnhost)` in the pass thru will evaluate against an empty variable.

**Fix:** In the pass thru, use `hdr(host)` directly in ACL definitions instead of
`var(txn.txnhost)`. The GUI-defined ACLs (which use `var(txn.txnhost)`) are fine
because they are evaluated at `use_backend` time, after `set-var` has run.

### 5. `userlist` in Global Advanced Pass Thru lands inside the `global` block

pfSense inserts Global Pass Thru content inside the `global` section. `userlist`
is technically a top-level HAProxy section, not a `global` directive. However,
HAProxy's section-based parser recognises `userlist` as a new section keyword and
implicitly closes `global`. The subsequent `frontend` keyword then closes the
`userlist` section. In practice this works despite the indentation.

## Reference: Final Generated Config Structure

```
global
    ...
    userlist imladris_users        ← Global pass thru (becomes its own section)
        user imladris password...

frontend HA_Frontend               ← closes userlist, opens frontend
    ...
    acl is_imladris_openmrs_auth hdr(host) ...    ← Frontend pass thru
    acl is_imladris_domain hdr(host) -m reg ...   ← Frontend pass thru
    http-request auth ... if is_imladris_domain   ← Frontend pass thru (scoped!)
    acl is_ha ...                                 ← GUI ACLs
    acl aclcrt_HA_Frontend ... imladrislab.org    ← GUI (duplicate #1)
    acl is_imladris_landing ...
    acl is_imladris_openmrs ...
    ... (other is_imladris_* ACLs)
    acl aclcrt_HA_Frontend ... ha.bipeds.org      ← auto-generated (duplicate #2)
    http-request set-var(txn.txnhost) hdr(host)   ← GUI generated
    use_backend HA_Server_ipvANY  if is_ha aclcrt_HA_Frontend
    use_backend Imladris_*        if is_imladris_* aclcrt_HA_Frontend

backend Imladris_Landing_ipvANY
    server landing 192.168.1.11:8090
...
```
